# Codex Window Reset v0.0.20

## 刷新全部额度不再多一次凭证列表往返

「刷新全部额度」此前会先 `GET /v0/management/auth-files`，再把拿到的 key 列表
回传给插件。这一步在 v0.0.18 及之前是**架构必需**的——那时由浏览器自己拼上游
Codex 请求，payload 里需要每个账号的 `auth_index`。v0.0.19 把这件事整体挪到
服务端、并让 `RefreshQuotas` 每批自己做一次账号发现之后，它就退化成旧架构的
遗留：既重复了服务端已经做过的发现，又在刷新前面加了一个可以独立失败、独立
超时（上限 15 秒）的前置依赖。

- `POST /quota-refresh` 的 `account_keys` 为空即表示「刷新发现到的全部账号」，
  批次由服务端权威决定。「刷新全部额度」因此只发一个请求。
- 该模式下账号发现失败会返回 `quota_refresh_failed`，而不是静默报告「无事可做」；
  显式指定 key 的请求维持原有的逐账号降级行为（失败账号保留旧快照）。
- 「立即检测」仍然拒绝空选择——手动检测必须显式选择账号是安全属性，没有被一并
  放宽。
- 只有当刷新结果里出现面板尚未显示的账号（会话期间新增或重新启用的凭证）时，
  才会补拉一次身份信息用于渲染表格行；该请求失败也不会影响已经拿到的额度结果。

注意：从服务器侧实测未能复现用户报告的「刷新全部卡住」现象（`/auth-files`
132–155ms、`/quota-refresh` 三账号 0.6–1.2s）。本次改动消除的是「多一个可独立
失败的前置依赖」这一类失败模式，而不是已确认的根因。

## 模拟器分段明细只保留策略 B

分段明细表原本把策略 A（首次使用，无预热的对照组）和策略 B（配置预热）的分段
混在一张表里，行首只有一个裸的 `A`/`B` 标记，说明文字只在上方卡片上，容易把
对照组的受限时段误读成自己的预热计划。现在明细只列策略 B，表头去掉「策略」列，
caption 标明「策略 B 配置预热」；时间轴上的 A/B 双泳道保留不变。

根因与回归证据见 [验证记录](../verification.md)。
