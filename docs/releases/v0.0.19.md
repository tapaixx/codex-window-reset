# Codex Window Reset v0.0.19

## 破坏性变更：管理接口路径改名，窗口重置功能下线

CLIProxyAPI 把 `/plugins/:id/quota`（GET/POST/DELETE）和
`/plugins/:id/quota/reset`（POST）保留给它自己的原生 Quota Provider SDK，
Gin 对静态路径的匹配优先级高于插件的通用转发兜底路由。本插件此前恰好把额度
展示和窗口重置注册在同名路径上，这两个请求从未真正到达插件代码：额度展示被
宿主原生 handler 接住并返回 `auth_index is required` 400，带审计的窗口重置
流程则从来没有执行过。

- `GET /quota` → `GET /quota-snapshot`，`POST /quota/refresh` → `POST /quota-refresh`。
- `POST /quota/reset` 下线。插件不再自己执行消费 Reset Credit 的重置——宿主
  自带的管理面板已经提供该能力；改用 CLIProxyAPI 的 Quota Provider SDK 去接
  会把这个不可逆操作暴露成任何调用方都能触发、绕开本插件确认弹窗与幂等键
  保护的全局入口。面板保留"重置额度"只读展示，仅移除执行按钮。
- 连带移除 Reset Audit 整套基础设施（`/reset-audit` 接口、审计持久化、面板
  审计标签页与 `DELETE AUDIT` 流程）——它唯一用途是记录插件自己执行重置的
  结果，重置动作没了就永远不会再产生新记录。

升级后如果浏览器仍缓存旧版面板，会请求已删除的 `/reset-audit` 并在控制台报
404，硬刷新一次即可。详见 [ADR-0021](../adr/0021-remove-self-service-quota-reset.md)。

## 修复：重装插件导致配置丢失

`defaultDataDir()` 此前把 `config.json`、`runtime-state.json`、`history.json`
直接写在 `/CLIProxyAPI/plugins/codex-window-reset/`——正是插件商店存放插件
自身安装产物的目录，重装/升级重建该目录就会连带删除 Operator 的配置与运行
状态。数据目录改为同级但不同名的 `/CLIProxyAPI/plugins/codex-window-reset-data/`，
首次启动时自动迁移旧目录中的数据文件，且只迁移一次、绝不用旧数据覆盖新数据。

## 修复额度刷新超时缺口与冗余账号发现

- 手动健康检测（探测前后）与窗口重置（消费额度前后）的额度刷新此前仍复用调用方
  未设期限的 context；上游额度接口卡住时会无限期挂起，与 v0.0.18 修复的自动预热
  阻塞是同一类根因，只是遗漏了这两条路径。现在两处都套用相同的 15 秒超时。
- 批量“刷新额度”改用插件自身的缓存路由后，配套的浏览器回归测试与夹具服务器
  已同步修复；一并修复了一个真实的展示缺陷——刷新失败的账号不再显示“已过期”。

## 性能修复

- 批量刷新额度不再逐账号重新发现整份账号列表（`accounts.Service` 本身不缓存，
  逐账号调用会把 N 账号刷新变成 N 次整表发现），改为整批共享一次发现结果。
- 面板首次加载的额度接口不再绕开 `ListAccounts` 已有的 5 秒缓存。
- 批量刷新完成后前端只重绘一次账号表，不再按账号数重复重绘整张表。

根因与回归证据见 [验证记录](../verification.md)。
