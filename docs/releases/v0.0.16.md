# Codex Window Reset v0.0.16

修复工作结束时间不与名义周期锚点对齐时，自动调度和模拟器仍漏掉后续预热的问题。

## 根因与修复

- 旧计划先生成工作开始后的 09:00、14:00、19:00 等名义锚点，再扣减提前量与错峰时长。工作到 18:00 时，19:00 在推导预热时间前就被丢弃，导致实际仍在工作内的 16:30 消失。
- v0.0.13 的结束边界修复只覆盖锚点恰好等于 19:00 下班的情况；v0.0.14 的浏览器样例也只验证该配置。v0.0.15 处理的是额度刷新和历史批次，未补齐这一边界。之前称预热轮次问题已彻底修复并不准确。
- 现在保留原有提前预热轮次，并继续推导与工作时段相交的预热窗口，再按每个账号的实际错峰时刻决定是否纳入。名义锚点在午休或下班之后，不再直接导致工作内的预热被丢弃。
- 下班时刻及之后不安排新槽位；先错峰再过滤，不把整段窗口裁短后重新分配，以免把原本下班后的请求提前。午夜末轮也保留原始窗口边界，只保留当天工作内的槽位。
- 跳过窗口仍按名义锚点的 HH:MM 匹配，禁用时段仍禁止请求。模拟器与自动调度继续共用同一个计划器，没有前端补造第三张卡片。
- 升级保留原有批次编号、账号错峰顺序及执行时刻，新增轮次使用未占用编号，防止插入中间轮次后重复执行已完成请求或绕过重启不补跑规则。概览仍按实际时间展示。

## 手算复现与防复发

Asia/Shanghai，2026-09-14，09:00–12:00 / 13:30–18:00，周期 5 小时、提前 120 分钟、错峰 60 分钟、单账号：

| 预热窗口 | 计划执行 |
| --- | --- |
| 06:00–07:00 | 06:30 |
| 11:00–12:00 | 11:30 |
| 16:00–17:00 | 16:30 |

- 先在计划器、模拟器和真实调度器接入测试中复现“仅两轮 / 没有 16:30 定时任务”，再修改生产逻辑。
- 回归覆盖：18:00 和 16:31 下班、恰好 16:30 下班、16:20 下班时不提前单账号槽位、双账号只保留 16:15、上午 11:30 续窗、名义锚点落在午休、禁用时段、跳过末轮、跨午夜以及原有 DST 规则。
- 真实调度器用真实计划器验证 16:30 任务持久化与单次执行，只替换时钟、存储和上游执行边界，不消耗真实账号额度。
- 升级回归用旧版已成功和待执行的持久化批次验证：插入上午续窗后，原下午批次不改编号或错峰时刻，不重复请求，不补跑重启前未执行的槽位。
- 浏览器的手写样例与 Go 导出样例统一改为 18:00 下班，直接断言概览三个窗口及三个执行标记；不再只检查 19:00 等号边界。原有 19:00 场景仍由 Go 测试覆盖。

包含 v0.0.15 的逐账号额度刷新与错峰历史批次分组。安装对应架构的新插件并重新加载后，页面顶部应显示 v0.0.16；无需删除配置或历史。计划执行仍受账号状态、额度充足判断和长窗口保护限制，不代表每一轮必然发送上游请求。已错过的计划不会补跑。
