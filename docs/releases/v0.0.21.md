# Codex Window Reset v0.0.21

本版只动面板，不改任何 host API 契约、调度行为或存储格式。改动来自一次完整的
UI 复查，findings 记录在
[UI Review Round 2](../superpowers/plans/2026-09-14-ui-review-round-2.md)。

## 模拟器不再用「策略 A / 策略 B」称呼两条线

时间轴泳道与指标卡此前只写裸字母，读者必须先做一次心智查表才知道行的含义。上个
版本里就出现过真实误读：策略 A 的 `10:30–12:30 预计受限` 被当成了自己 11:20 的
预热计划报为 bug，而那条线是**不预热的对照基准**，行为完全正确。

- 泳道改为 `不预热 / 对照基准` 与 `按计划预热 / 已配置计划`。
- 指标卡改为 `不预热可用` / `按计划预热可用`。
- 策略卡片去掉 达标/未达标 徽章，改为直接写 `覆盖工作时段 N%`。徽章依赖的
  `health_threshold_percent` 从未被调度器读取，该输入框一并从配置表单移除
  （字段本身仍在 API schema 中，保存请求不受影响）。

## 账号表 16 列 → 12 列

- `AUTH INDEX` 与 `账号前缀` 折进账号单元格的次行。两者只在排查时用于交叉引用，
  此前各占一整列。
- `请求结果`、`窗口结果`、`HTTP / 耗时` 描述的是同一件事——上一次检测。三列合并
  为单个 `上次检测` 徽章，明细紧随其后。
- 表格 `min-width` 从 1420px 降到 1180px。原值会在 1440 视口下强制产生一条横向
  滚动条。

## 额度快照新鲜度有了全局呈现

面板刻意不做轮询（ADR-0011，并有测试守住「无轮询定时器」）。代价是刚打开的面板
会用和实时数据完全相同的视觉权重渲染几小时前的额度。

工具栏新增快照新鲜度指示，报告**最旧**一份快照的年龄，并按 5 分钟 / 30 分钟两档
降级配色；尚无快照的账号数量一并标出。

## 首次安装不再「什么都没发生」

新装插件按设计是惰性的（规范验收标准），但此前只有帮助弹窗解释这件事。计划未启用
时，面板现在常驻一份三步清单——配置预热提前量与时长 / 勾选账号 / 保存并启用——
满足一项打勾一项，可手动关闭。

## 其他

- Guardrail Hold 是唯一真正阻止自动预热的状态。它在 0 时淡出，非 0 时整块升级为
  警示态，不再以和 健康/暂停 相同的权重恒占一格。
- 会真实调用上游的操作（刷新额度、立即检测）加前导圆点与实心样式，与只读/本地
  操作区分；`刷新面板` 降级为标题栏的 `重新载入`。
- 修复 `withQuotaRefresh`：行内刷新按钮会被 `renderAccounts()` 销毁重建，把它们
  放进 `previous` 数组意味着 `finally` 里的状态恢复写在了已分离的节点上。此前
  行为正确纯属 `renderAccounts()` 随后用已清空的 `quotaBusy` 重算了一遍的顺序
  巧合。现在行内按钮的禁用态只由 `renderAccounts()` 决定。
- 浅色模式 `.simulation-assumptions` 对比度 4.42 → 达标；行操作按钮 36px → 40×40。

复查中唯一**保留未改**的项：时间轴上的预热时间点标记维持 24px 宽。撑到 40px 命中
区后，点标记会和同一泳道上的短时段色块无法区分，而这正是该标记要避免的混淆；
可点击性由 76px 高度与 hover/focus 提示承担。

`gofmt` / `go vet` / `go build` / `go test` / `go test -race` 全部干净；
