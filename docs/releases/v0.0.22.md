# Codex Window Reset v0.0.22

修复一个使自动预热**完全不会执行**的调度缺陷。建议所有使用自动预热的部署升级。

## 症状

配置正确、计划已启用、账号已勾选，但预热从不发生，检测历史里连一条跳过记录
都没有。手动「立即检测」正常。

## 根因

`Scheduler.Start()` 会把上一个进程遗留的所有 `planned` 状态槽位标记为 missed，
并且**刻意包含预热窗口尚未开始的未来槽位**。而 `Reconcile()` 只会刷新仍处于
`planned` 状态的槽位——被标记 missed 之后没有任何路径能让它复活。

于是一次重启之后，整个 8 天计划视野被清空，只剩下「今天新滚入视野的那一天」
是有效的；而下一次重启（升级插件、重载配置、容器重启）又会把它也清掉。
`ExecutePreheat` 对 missed 槽位直接返回，连历史记录都不写——所以现象是
「什么都没发生」。

在报告问题的部署上，81 个槽位中有 72 个是 `missed / restart`，覆盖到
2026-09-21 为止的每一天，最近的一个定时器在 7 天之后。

## 修复

ADR-0015 的原文范围是「预热窗口**已经开始或已经结束**」时未执行的槽位记为
missed——「即使窗口还剩一部分」，而不是整个未来。

- `Start()` 改用这个边界：窗口已开始/已结束的 `planned` 槽位、`running` 槽位、
  待补偿槽位仍然记为 missed 并撤销定时器；窗口尚未开始的槽位原样保留，由随后的
  reconcile 重新挂上定时器。
- `Reconcile()` 会复活「已标记 missed 但窗口尚未开始」的槽位。missed 槽位从未
  发出过任何请求，因此复活它不可能产生重复请求；这条路径同时修复了受影响版本
  已经写坏的持久化状态，**升级后无需删除任何文件**。
- 不改变「不补跑」语义：窗口已开始或已过的槽位仍然不会补跑。

## 验证

- 新增回归：重启后未来窗口保持 `planned` 并如期触发；已到期槽位仍记为 missed
  且不挂定时器；reconcile 复活未来 missed 槽位但不复活已过期的。
- 原有「升级不重放旧批次」回归保持通过——它正是窗口已开始的场景。
- 用报告问题的部署的真实 `runtime-state.json` + `config.json` 接入真实计划器
  重放 `Start` + `Reconcile`：69 个槽位重新挂上定时器，最近一次在当地时间
  10:31，其余 12 个确实已过期的保持 missed。
- `gofmt` / `go vet` / `go build` / `go test` / `go test -race` 全部干净；
  `node --test web/tests/*.test.mjs` 70 通过 0 失败。

## 升级后预期

重载插件后，面板的检测历史应在下一个预热窗口出现记录。注意记录出现不等于一定
发送了上游请求：账号状态、额度充足判断（短窗口余量高于下限且距重置时间足够）
和长窗口保护仍可能把某一轮判定为跳过，这类跳过会作为一条带原因的记录出现，
与本次修复的「完全没有记录」是不同的现象。
