# Codex Window Reset v0.0.28

修复账号标识的遮罩被击穿:面板上遮住的邮箱可以从同一格里的另一行拼回来。

## 账号标识不再交还邮箱

账号单元格此前显示:

```
a***@qq.com
身份已遮罩
** · alex_***.com
```

第三行是账号标识按「首段 + `***` + 尾段」遮罩后的结果。但它装的是**操作者的邮箱**,
于是这个遮罩把本地部分和域名一并交还,和上一行遮罩过的邮箱并排,完整地址就被拼了
回来。遮罩形同虚设。

该字段本就不该装地址。主机的 `account` 与 `id` 都不是账号标识:`account` 就是地址
本身,`id` 把地址嵌在文件名里(`codex-03c103fb-alex_nnn@qq.com-team.json`)。而真实
的 auth-files 响应**根本没有顶层 `account_id`**,于是 Go 投影与面板的主机归一化都
沿着兜底链落到了这两个字段上。

- 两侧现在只读 `id_token.chatgpt_account_id`,不再有任何其他兜底。
- 没有账号标识的账号如实报告为空,不再拿地址顶替。

## 遮罩本身加固

- 含 `@` 的值按**地址**遮罩,不再首尾外露。
- 长度不足 16 个字符的标识**整体遮蔽**——短值露出首尾就等于露出大半。
- 长的不透明标识仍保留 4+4,这正是它有用的地方:可以看出哪些凭证共用同一个
  ChatGPT 账号。

现在显示为 `** · 5417***8d01`。

## 检测历史跟随「显示身份」开关

检测历史一直使用服务端固定的 `masked_identity`,完全不理会开关。打开「显示身份」后,
账号表与即将执行显示真实地址,而历史仍是遮罩状态——同一页面给出两个答案。

所有身份现在统一经过账号列表与当前开关,开关也会一并重渲染历史面板。

## 发版流程精简

一次 tag 推送会同时触发 CI 与 Release,两者针对同一个 commit;而各自又都跑了两遍
检查——CI 有 verify 与架构矩阵,Release 带着一份逐字相同的架构矩阵,外加又一次完整的
Go、race 与浏览器测试。**同一套测试在一次发版里跑了四遍**,不产生任何 CI 未给出的
信号。

Release 现在只负责构建、打包、校验自己产出的资产、发布。产物布局的冒烟测试保留——
它检查 zip 内容与资产命名,属于发布专有、别处不覆盖。CI 仍是完整门禁,同一次推送上
照常运行全部检查。

## 验证

- 回归直接使用实时 auth-files 响应的形状(无顶层 `account_id`,`account` 为地址,
  `id` 内嵌地址),断言账号标识既不含 `@`、也不含本地部分,并断言遮罩后的整行无法
  重建地址。
- 浏览器回归覆盖三处面板在开关两种状态下的一致性。该用例**最初对着缺陷也会通过**:
  它未限定选择器,而即将执行的行同样带有 `history-batch-item` 类且在 DOM 中更靠前,
  读到的是另一个面板。限定到 `#history-output` 后,对旧代码如期失败。
- `gofmt` / `go vet` / `go build` / `go test` / `go test -race` 全部干净;
  `node --test` 122 通过 0 失败。
