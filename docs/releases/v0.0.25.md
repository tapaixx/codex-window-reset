# Codex Window Reset v0.0.25

修复一个把**几乎未使用的额度窗口读成已耗尽**的解析缺陷。该缺陷同时影响面板显示
与 Guardrail 判定,建议立即升级。

## 用量单位按字段名判定,不再从数值猜测

解析器此前把任何落在 `[0,1]` 区间的用量值乘以 100,理由是"它一定是小数"。这个
规则**无法区分「1 个百分点」和「小数 1.0 = 整个窗口」**。

报告问题的部署上,实时上游响应为:

```json
"primary_window": { "used_percent": 1, "limit_window_seconds": 18000, "reset_at": 1789493450 }
```

即用掉 **1%**、剩余 **99%**。旧规则读成用掉 100%,面板显示 **0%**,而同一响应里的
重置时间被正确渲染在旁边。刷新永远无法纠正,因为每次都用同样的方式算错——数值
不是陈旧,是**一直算错**。

**同样的误读发生在长窗口上后果更严重**:余量被算成 0%,而 `0 ≤
long_window_floor_percent`,于是账号进入 Guardrail Hold,被挡在**所有**预热之外,
而它实际握有 99% 的周额度。

- 单位现在由字段名决定:`used_percent` / `usedPercent` / `used` 是百分比,不缩放;
  `used_fraction` / `usedFraction` 按小数缩放。
- `remaining_percent` 分支存在**反方向**的同款缺陷(`remaining_percent: 1` 会显示
  成剩余 100%,把耗尽的账号报成满的),一并修复,并补上 `remaining_fraction`。
- 前端 `normalizeCodexQuota` 带有完全相同的启发式,同步修复。
- 两个现存测试以 `used_percent` 小于 1 的取值断言了旧行为,把缺陷写成了契约;现已
  改为覆盖百分比与小数字段的真实区分,并新增一条直接使用上述真实 payload 的回归。

> 该缺陷之所以被发现,是因为 v0.0.24 开始把上游自己的判决与百分比并排显示:同一行
> 同时出现「0%」与「上游报告仍可请求」。在那之前,面板只显示一个看起来权威的 0%,
> 刷新一百次也无法证伪。

## 完成的探测一律视为预热成功

探测此前要求模型回复**恰好是 `OK`**,否则记为 `unexpected_output`(失败)。

而 `ParseCompleted` 已经会拒绝 `response.failed` / `response.incomplete` / `error`
并要求 `response.completed` 携带文本——走到文本判断即意味着模型真的完成了一次响应、
额度已被消耗、**窗口已经打开**。

旧规则下,只要模型加个标点、改个大小写或用另一种语言作答,一次**完全成功**的预热
就会记为失败,它打开的窗口会被记为 `not_observed`。该状态不可补偿,因此不会触发
重试,危害限于报告层——但那正是让面板不可信的那一类缺陷。

`unexpected_output` 现在仅表示"完成了但没有任何文本"。

## 管理响应一律标记为不可缓存

插件此前**不发送任何缓存指令**——API 响应与面板的 HTML、JS 模块都没有。前置 CDN
只能按自己的启发式决定是否缓存。

它提供的东西没有一样可以复用:API 是实时状态,面板资源必须与正在运行的构建匹配。
升级会同时改变两者,而被缓存的面板会继续投递旧 UI,其资源引用已经失效,表现为
**空白页**;源站全程健康,服务端检查看不到任何异常。

所有响应(含资源读取与错误信封)现在携带
`Cache-Control: no-store, no-cache, must-revalidate, max-age=0`,并附 `Pragma` 与
`Expires` 兼容旧中间层。`Allow` 等附加响应头不受影响。

> 若 CDN 侧配置了 "Cache Everything" 一类强制规则,它会覆盖源站指令。此时仍需在 CDN
> 上为管理接口与面板设置 Bypass。

## 本次一并完成的排查

按「从数值猜语义」这一模式对全仓做了定向排查。以下位置检查后判定安全:
`timeValue` 的秒/毫秒判定(歧义区在现实中不可达,与百分比不同)、窗口时长的单位
字段、`numberValue` 的类型分支、`firstBool` 的布尔解析、两份 `shortestIndex` 实现的
一致性、`ValidateConfig` 对越界值报错而非静默替换、以及 `local_time.go` 中显式的
DST 消歧。

## 验证

- 新增回归直接使用上述真实上游 payload,断言短窗口余量 99%、长窗口 68%。
- 单位测试覆盖 `used_percent: 1` / `0.25` / `30`、`used_fraction: 0.3` / `1`、
  `remaining_percent` 与 `remaining_fraction`。
- 探测测试覆盖"措辞不同的完成"判为成功、"完成但无文本"判为 `unexpected_output`。
- 缓存头测试覆盖正常响应、资源、未知路由与 405 四条路径,并断言 `Allow` 不被覆盖。
- `gofmt` / `go vet` / `go build` / `go test` / `go test -race` 全部干净;
  `node --test` 111 通过 0 失败。

## 升级后预期

此前显示 0%、旁边带「上游报告仍可请求」的账号,刷新后应显示真实余量。因误读而进入
Guardrail Hold 的账号会在下一次额度刷新后自动解除。升级后建议**硬刷新一次面板**
(Ctrl+Shift+R),确保加载的不是被缓存的旧 UI。
